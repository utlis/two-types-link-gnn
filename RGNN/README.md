# RGNN Internal Behavior

This document describes the current GNN behavior in this directory. It is a
code-level summary, not a proposed new algorithm.

## Edge Type Convention

The project-facing names are:

| Project label | Internal id | Meaning |
| --- | ---: | --- |
| Type 1 | 0 | Composition edge: connects adjacent tokens in a term |
| Type 2 | 1 | Term-link edge: connects the first token to the last token |

The internal ids remain `0` and `1` for compatibility with saved datasets and
models. Logs and CSV outputs should use the project-facing Type labels.

## Dataset Creation

Entry points:

- `create_dataset.py`
- `batch_create_dataset.py`

The dataset builder reads a term list from either:

- one CSV/TXT file via `--data_path`, or
- pre-split `--train_path`, `--dev_path`, and `--test_path`.

For each term:

1. The term is tokenized by `data_loader.tokenize`.
2. Each token is mapped to a node id in `vocab`.
3. If the term has one token, a Type 2 self-link is created.
4. If the term has two or more tokens:
   - Type 1 composition edges are created between adjacent tokens.
   - One Type 2 term-link edge is created from the first token to the last token.

Duplicate `(src, dst, relation)` triplets are removed when building the graph.

Node features are:

- FastText vectors when `--use_embedding` is set.
- Identity vectors when no embedding model is used.

## Split Construction

There are two split modes.

### Pre-Split Mode

When `--train_path`, `--dev_path`, and `--test_path` are given, edges are built
from each file separately.

The code removes dev/test edges that already appear in earlier splits:

- dev edges overlapping train are removed.
- test edges overlapping train or cleaned dev are removed.

This reduces direct edge leakage across splits.

### Internal Split Mode

When only `--data_path` is given, edges are split by `split_edges_stratified`.
This keeps the relation-type ratio roughly similar across train/val/test.

## Negative Sampling

Negative edges are generated by `data/dataset.py::sample_negative_triplets`.

Current behavior:

1. For each positive edge `(src, relation, dst)`, the sampler corrupts the head,
   the tail, or either side depending on `--corrupt_mode`.
2. It rejects the sample if that triplet already exists in any positive split.
3. Candidate nodes are sampled uniformly, by positive-graph degree, or by a
   50/50 mix depending on `--hard_negative_mode`.
4. If it cannot find a strict negative after 100 tries, it falls back to a random
   destination.

Supported `--corrupt_mode` values:

- `tail`: generate `(src, relation, random_dst)`.
- `head`: generate `(random_src, relation, dst)`.
- `both`: randomly choose head or tail corruption per sample.

Supported `--hard_negative_mode` values:

- `none`: sample corrupt nodes uniformly.
- `degree`: sample high-degree nodes more often.
- `mixed`: use uniform sampling for half of samples and degree sampling for half.

## Model

The main model is `models/rgcn_distmult.py::RGCNLinkPredictor`.

It has two parts:

1. Encoder
   - Default: `RGCNEncoder`
   - Optional: `RGATEncoder`
   - Optional: `CompGCNEncoder`
   - Input: node features, message-passing edge index, edge types
   - Output: node embeddings

2. Decoder
   - Default: `ComplExDecoder`
   - Optional: `DistMultDecoder`
   - Input: source node embedding, relation embedding, target node embedding
   - Output: one logit score per target edge

Default command behavior uses RGCN + ComplEx.

`CompGCNEncoder` lives in `models/compgcn_encoder.py` and is imported by the
shared predictor. It composes source node features with relation embeddings
before aggregation, then updates relation embeddings across layers. Use
`--encoder compgcn` or the shortcut script `train_compgcn.py` to run it.

## Training

Entry point:

- `train.py`
- `train_compgcn.py` for the CompGCN encoder shortcut

Available encoders:

- `rgcn`
- `rgat`
- `compgcn`

Available decoders:

- `complex` (default)
- `distmult`

For each epoch:

1. Positive train edges are used as the message-passing graph.
2. The encoder computes node embeddings.
3. The decoder scores train positive edges and sampled train negative edges.
4. The default loss is balanced BCE with logits.
5. Validation runs every `--eval_every` epochs.
6. The checkpoint with the best validation AUC is saved.
7. Early stopping is based on validation AUC.

After training:

1. The best validation checkpoint is loaded.
2. The validation set is used to find an F1-maximizing probability threshold.
3. The test set is evaluated with that threshold for binary metrics.
4. Filtered ranking metrics are computed by corrupting both head and tail nodes.
5. Test metrics are saved to `test_metrics.csv`.

The binary metrics are:

- `auc`
- `ap`
- `acc`
- `precision`
- `recall`
- `f1`

The ranking metrics are:

- `mrr`
- `hits_at_1`
- `hits_at_5`
- `hits_at_10`

Ranking evaluation uses all nodes as corruption candidates. Known positive
triples from train, validation, and test are filtered out, except for the
current target triple. Each positive test edge contributes both a head-corruption
rank and a tail-corruption rank.

The per-type metrics are reported using project labels:

- `relation_type=1`: composition edges
- `relation_type=2`: term-link edges

## Trained Dataset Output

At the end of `train.py`, a `trained_dataset.pt` file is saved next to the input
dataset.

It contains:

- train positive edges
- val positive edges
- test positive edges predicted above the chosen threshold
- test negative edges predicted above the chosen threshold
- the optimal threshold

The final `edge_index` stored in `trained_dataset.pt` is:

```text
train positives + val positives + predicted-positive test positives
```

False-positive negative edges are stored separately as
`predicted_test_neg_edges`.

## Reconstruction

Entry point:

- `reconstruct_terms.py`

Current reconstruction uses the two edge types as follows:

1. Type 1 composition edges build a directed NetworkX graph.
2. Type 2 term-link edges provide `(src, dst)` target pairs.
3. For each Type 2 pair, the code searches a path from `src` to `dst` through
   the Type 1 graph.
4. The node ids in the path are converted back to tokens and joined as a term.

With `--predicted_only`, the target Type 2 pairs come from predicted test edges
stored in `trained_dataset.pt`.

With `--prediction_only_eval`, both the Type 1 graph and the Type 2 target pairs
come only from predicted edges.

The default pipeline reconstruction mode uses `--predicted_only`, so negative
test samples predicted as positive are not used as term targets unless
`--include_predicted_negatives` is explicitly enabled.

## Current Issues And Improvement Points

### 1. Message Passing Uses Only Train Positive Edges

During training and evaluation, the encoder message-passing graph is the train
positive graph. Validation/test positive edges are not used for message passing,
only for scoring.

This is a conservative choice for leakage control, but it also means isolated
test-only structures may be hard to score.

Recommended check: compare with a transductive setting that uses train+val
positive edges for final test encoding after model selection.

### 2. Decoder Choice Still Matters

The current default decoder is ComplEx because the edge directions matter.
DistMult is still available for ablation, but it is symmetric in source/target
for a fixed relation and may be too limited for directed token-order relations.

Recommended check: compare `complex` and `distmult` under the same seed,
encoder, negative sampling, and thresholding settings.

### 3. Term Reconstruction Depends Strongly On Type 1 Connectivity

The final term-level result is not only a link prediction problem. Even if a
Type 2 term link is predicted, reconstruction fails when there is no Type 1 path
between the two endpoint nodes.

Recommended check: report reconstruction failure counts separately from link
prediction metrics.

### 4. F1 Threshold Can Become Very Low

The optimal threshold is selected by validation F1 over thresholds from `0.01`
to `0.99`. In existing runs, the chosen threshold can be very low. This may
increase recall but also include many predicted edges.

Recommended check: report metrics at both the F1-optimal threshold and fixed
thresholds such as `0.5`.

### 5. Term-Level Precision Is Filtered By Reconstruction

The term-level evaluator only compares reconstructed term strings. In the
default `predicted_term_links` mode, predicted negative Type 2 samples are not
included as term targets. Also, Type 2 predictions with no Type 1 path do not
produce output terms. This creates a filtering effect that can make term
precision look high.

Recommended check: report term metrics separately for single-token and
multi-word terms, and add a stricter term evaluation that counts predicted Type
2 targets with no reconstructed term as false positives.

### 6. `shortest_only` Does Not Use `cutoff`

When reconstruction uses `--shortest_only`, the code calls
`networkx.shortest_path`, which does not apply the configured `cutoff`. The
`cutoff` value is only used by the all-simple-path mode.

Recommended fix: reject shortest paths longer than `cutoff` or document that
`cutoff` is ignored when `shortest_only` is enabled.
